# M3 · Choose a language and YouTube channel for each Short

**Outcome.** Select an idea and its production language, make one Short, then privately upload it to a chosen YouTube channel. English and Russian are the first supported languages. A Russian Short can start directly in Russian. If the editor later requests another language, that adaptation gets its own script, timing, cover, approval and destination.

## Why this is the next stage

M2 produced four public reference cuts of two explanations. The release process still needed local, untracked scripts to create localized records, author diagram specifications, assemble storyboards, set YouTube language fields and repair stage rows. Sourcing more ideas would fill the inbox while leaving the same work for every release. Prioritize the production workflow. Discovery can proceed independently against the existing idea, evidence and selection contract. Use the shipped cuts as editorial references and a fresh topic as the release test. [Eclipse, English](https://www.youtube.com/shorts/PBE2c9RPK08) · [Eclipse, Russian](https://www.youtube.com/shorts/eJaDyzMw3yM) · [Orbital free fall, English](https://www.youtube.com/shorts/uYrv89Drdc8) · [Orbital free fall, Russian](https://www.youtube.com/shorts/shTQx_cgV50)

## Implementation order

### 1. Choose the language and destination independently

Selecting an idea creates one project in the language the editor chooses. Write the hook, beats, outro, labels, captions and upload copy in that language. Produce one narration and timeline. An optional **Adapt to another language** action can start from any supported language, even after publication. Link the new project to the approved source revision and evidence, and give it independent review. Repeated submissions of the same creation request return the same project. A later editorial request may reuse the idea.

Give each connected YouTube channel a profile with its immutable provider/channel ID, display label and a reference to its credential binding. The picker shows the connected channels. An optional language default can suggest a destination, which the editor may override. Save the chosen channel ID on the project. A language can be used on several channels, and one channel can accept several languages. Require a verified destination for real upload. A local project can reach its final render before a channel is connected.

At script review, associate factual statements in the hook, beats and outro with a claim and an evidence quote. Flag changed or uncovered statements. The editor checks the quotation in context. An adaptation preserves the mechanism, numbers, units and sources. Make duration an editorial setting. The writer asks for 45–60 seconds today, while the reference cuts run roughly 36–42 seconds.

**Accept when** starting directly in English or Russian produces exactly the requested project and one set of production calls. Changing a routing default leaves saved destination IDs intact. An on-demand adaptation can pick its own language and channel, and editing it preserves the source script, approvals and remote ID. Retain legacy project IDs and allow explicit language assignment where unknown.

### 2. Author the visual explanation in the storyboard

Offer a beat-level choice of a supported diagram and focus, editable object labels where applicable, flow steps, stock or still. Include hook and outro. Validate and save the choices as a storyboard revision, timed to the chosen narration. An optional adaptation can copy the visual intent and override its labels or focus. Keep the existing asset replacement and visual-review lock. Flag missing assets and unsupported diagram types before spending on replacements. Ask the editor to judge whether the visual actually explains the mechanism.

**Accept when** the editor can reproduce a known spatial sequence and build a new explanation from supported components without writing TypeScript or editing database rows. Switching one focus or label invalidates only the affected visual work and its dependent preview/final. Reopening the review shows the saved revision. A newly required physical mechanism can be scoped as an additional renderer component.

### 3. Review a quick preview and design a cover

Generate a lower-resolution video from the edited storyboard, saved assets, audio, captions and template before requesting a full render. Give the editor play, revise and render-final actions. Distinguish draft preview, final MP4, its extracted poster and the independently editable cover in storage and UI. Support a simple local design from a chosen frame, crop and optional localized cover text. Keep the cover outside the video's opening.

**Accept when** the editor can select a frame, export a portrait cover with text in the selected language and play a draft before the first full encode. Log cold and warm timings for the same project and show that the draft returns sooner than the full render. Editing invalidates stale previews and covers as applicable. The upload gate accepts only the specifically approved full render. Verify the supported cover-selection path on the target Shorts surface and record what actually appears there. If a separate cover file cannot be applied, provide the export and instructions for selecting an eligible video frame, and display the actual remote outcome separately.

### 4. Select and audition a soundtrack

Let the editor choose voice only or upload/select a licensed instrumental, record its provenance, permitted use and credit, and audition the track under speech. Store the selection and gain with the cut, feed the same mix to preview and final, reuse the loop/duck/fade envelope, normalize differing track levels and include any required credit in the description. Basic local mixing needs no new API key.

**Accept when** a test track shorter than the narration loops cleanly through a scene boundary, speech stays intelligible, fades reach the edges cleanly, and the mixed file passes a peak check. Use a generated test tone or an owned fixture for automated checks. Key render reuse on the chosen track revision and mix settings. Switching tracks creates a new mix without synthesizing the voice again or altering any linked project. Voice only remains a complete release path.

### 5. Publish the reviewed version to the selected channel

At the private-upload gate, display the destination label and channel ID beside the approved render, title, description, tags, credits, disclosure, audio language and default metadata language. The publish/schedule gate shows that same destination, remote video ID and reviewed metadata. Bind upload approval to the project, render, channel and metadata revision. Bind publishing and scheduling to that reviewed revision and its specific remote upload. Before each remote mutation, verify that the authenticated channel matches the saved ID. Show a fixable credential error if it differs.

Scope resumable sessions, upload rows and retry lookups to channel ID plus render ID. Preserve existing upload history. Changing the destination invalidates pending upload/publish approvals. After approval, reuse the local render for the new destination and create a distinct remote record. The original upload keeps its channel, remote ID, privacy and schedule. Reconnect credentials by verifying channel identity. For old uploads, retain their remote IDs and bind the original channel only after checking ownership. Keep unresolved records visible for reconciliation. Migration itself issues no upload or privacy writes.

Include effective provider, model, voice, template, asset and mix settings in the hashes of stages that consume them. Checkpoint paid audio before local processing, reuse completed assets, surface skipped mastering/pause processing, and make a necessary paid retry visible. Persist schedules as explicit instants with the reviewer's time zone. A scheduled upload stays private until a remote read confirms publication. [Stage runner](../apps/pipeline/src/stages/runner.ts) · [Voice stage](../apps/pipeline/src/stages/voice.ts)

**Accept when** replays reuse the remote ID for the approved channel/render pair. A stale approval after a destination or metadata change, or credentials for a different channel, causes zero remote writes. Changing destination after private upload and approving again produces two independent channel records. A visual edit reuses the approved voice, a voice change invalidates its dependent timeline, and interrupted mastering resumes from saved audio. A simulated schedule moves from scheduled to public only after remote confirmation.

## Release rehearsal

Build language selection and channel profiles first. Storyboard editing then feeds preview, while channel-bound publishing can proceed in parallel. Finish soundtrack audition against the preview, integrate the final render gate, and rehearse the entire flow.

- **Editorial acceptance.** Take a fresh sourced topic through Ideas/Projects as a single video in the chosen language using the shipped template and components. Review evidence, mechanism, labels, numbers and phrasing in that language. A reviewer can locate the approved script, storyboard, destination and publication decision in the dashboard. Topic-specific code, untracked scripts, direct database repairs or post-upload language patches leave this rehearsal incomplete.
- **Picture and sound.** Inspect phone-size drafts and extracted frames from the 1080×1920, 30 fps final. Inspect the full timeline including the hook, scene transitions and outro. Every interval must carry a deliberate visual, including a deliberate hold or continuation. Repair blank frames, plain-background gaps and unsupported diagrams. Fill and center the explanatory animation. Labels name parts, objects or quantities. Begin immediately with the visual. Keep opening titles, source banners and AI banners out of the video. Put sources/credits and accurate synthetic-media metadata in the upload. The reference cuts with native explanatory SVGs used `containsSyntheticMedia=false`.
- **Caption and narration baseline.** Bundle Latin and Cyrillic Inter. Keep captions centered, fixed at 64 px in the final, up to three words per phrase, with a raised bottom placement at 68% or the established top option where the subject needs it. Preserve fixed sizing and whole-phrase display without karaoke highlights. Use ElevenLabs Jade (`g7LVvkPWALzPxOQbF6OE`), `eleven_v3`, natural pace, stability 0.5, character-based alignment and forced-alignment fallback. Preserve the 0.25 s pause cap and the low shelf/compression plus −14 LUFS narration target. Check the mastered audio against caption timing for the selected language, then listen to the final mix. [Caption geometry](../apps/renderer/src/props.ts) · [Caption chunks](../apps/renderer/src/captions.ts) · [Mastering](../apps/pipeline/src/audio/mastering.ts)
- **Engineering acceptance.** Add CI for `pnpm typecheck`, `pnpm test` and `pnpm test:e2e` at M3 start. Drive two independent projects, one English-only and one Russian-only, through the dashboard, Inngest, Postgres and real Remotion with fake paid ports. Assert zero unrequested translations, narrations or renders. Route each to a different fake channel, reverse the configured language defaults, then override the suggested channel on a new project. Confirm existing projects and retries retain their chosen IDs. Exercise a stale approval, wrong credential identity, a destination change after private upload and a restart. In a separate test, request an adaptation and verify the original project's artifacts and remote state. Include music and voice-only mixes.
- **Channel acceptance.** On a connected channel, play an approved private upload on a phone. Verify its owner channel ID, language fields, metadata, disclosure and privacy against the stored record. If the owner connects two channels, verify private routing on both. Record the fake-channel results and which live destinations were verified. Use the normal gate for a video intended for release. Record measured preview/full render times, corrections and paid calls.

## Input from the channel owner

During channel setup, connect the destinations you want and optionally set a suggested channel for each language. The editor can choose the destination per video, so the final language-to-channel mapping can wait. Keep manual approvals and use voice only unless a licensed track is selected. An instrumental with its credit terms and a mood reference would help test music. An example where depth changes the explanation would guide the first 3D trial. An intended release time and timezone would allow a live scheduling check. Hosting, auto-shortlisting and additional provider budgets can wait for their milestones.
