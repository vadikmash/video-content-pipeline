# M3 · Make bilingual Shorts repeatable

**Outcome.** From one evidence-backed idea in the dashboard, an editor can produce an English Short and a Russian Short, review each at phone size, and approve each for private upload. Each cut has its own timing, cover, metadata and publication decision. The pipeline can explain which script, assets and render reached YouTube.

## Why this is the next stage

M2 produced four public reference cuts of two explanations. The release process still needed local, untracked scripts to create localized records, author diagram specifications, assemble storyboards, set YouTube language fields and repair stage rows. Sourcing more ideas would fill the inbox while leaving the same work for every release. Build the dashboard workflow first. Use the shipped cuts as editorial references and a fresh topic as the release test. ## Implementation order

### 1. Start two language cuts from one idea

Keep one project per language cut so stages, approvals and uploads retain their existing project IDs. Allow a second project for the same idea through a dashboard action, including after the first cut has shipped. Store a stable language, a link to the source script revision and the evidence the two cuts share. Let the editor start with English only or add Russian later. Show the language and sibling project's status on the project list and detail view.

Generate an editable adaptation preserving the mechanism, numbers, units and source links. At script review, associate each factual beat, including the hook and outro where applicable, with a claim and an evidence quote. Flag changed or uncovered claims for correction before approval. The reviewer checks the quotation in context and whether it supports the spoken claim. Keep this usable with human-supplied evidence while real research is deferred. Make the intended length an editorial setting. The writer currently asks for 45–60 seconds and the reference cuts run roughly 36–42 seconds. Size each cut to its narration.

**Accept when** selecting the idea twice or retrying variant creation yields one cut per requested language. An editor can correct a Russian sentence and its evidence, approve that script revision, and generate its own narration and timings. English approvals and artifacts survive. An older single-project record retains its identity, artifacts and remote ID. For legacy records with unknown language, allow explicit assignment without assuming that every existing cut is English.

### 2. Author the visual explanation in the storyboard

Offer a beat-level choice of a supported diagram and focus, editable object labels where applicable, flow steps, stock or still. Include hook and outro. Validate and save the choices as a storyboard revision, retiming each language to its own words. Carry shared visual intent across translations, allow per-cut overrides, and keep the existing asset replacement and visual-review lock. Flag missing assets and unsupported diagram types before spending on replacements. Ask the editor to judge whether the visual actually explains the mechanism.

**Accept when** the editor can reproduce a known spatial sequence and build a new explanation from supported components without writing TypeScript or editing database rows. Switching one focus or label invalidates only the affected visual work and its dependent preview/final. Reopening the review shows the saved revision. A newly required physical mechanism can be scoped as an additional renderer component.

### 3. Review a quick preview and design a cover

Generate a lower-resolution video from the edited storyboard, saved assets, audio, captions and template before requesting a full render. Give the editor play, revise and render-final actions. Distinguish draft preview, final MP4, its extracted poster and the independently editable cover in storage and UI. Support a simple local design from a chosen frame, crop and optional localized cover text. Keep the cover outside the video's opening.

**Accept when** the editor can select a frame, export a portrait cover for each language and play a draft before the first full encode. Log cold and warm timings for the same project and show that the draft returns sooner than the full render. Editing invalidates stale previews and covers as applicable. The upload gate accepts only the specifically approved full render. Verify the supported cover-selection path on the target Shorts surface and record what actually appears there. If a separate cover file cannot be applied, provide the export and instructions for selecting an eligible video frame, and display the actual remote outcome separately.

### 4. Select and audition a soundtrack

Let the editor choose voice only or upload/select a licensed instrumental, record its provenance, permitted use and credit, and audition the track under speech. Store the selection and gain with the cut, feed the same mix to preview and final, reuse the loop/duck/fade envelope, normalize differing track levels and include any required credit in the description. Basic local mixing needs no new API key.

**Accept when** a test track shorter than the narration loops cleanly through a scene boundary, speech stays intelligible, fades reach the edges cleanly, and the mixed file passes a peak check. Use a generated test tone or an owned fixture for automated checks. Key render reuse on the chosen track revision and mix settings. Switching tracks creates a new mix without synthesizing the voice again or changing the other language. Voice only remains a complete release path.

### 5. Publish the reviewed version and recover cleanly

Bind script, storyboard, final render, metadata revision, upload and gate actions to the specific cut and approved IDs. Present editable localized title, description and tags plus source/music credits, disclosure, and audio/default language before private upload. Preserve the existing resumable-upload record. Verify metadata and visibility by reading the remote video. Handle an interrupted send, stale approval and duplicate click without an extra upload or silent advance. Include effective provider, model, voice, template, asset and mix settings in the hashes of stages that consume them. Checkpoint reusable paid output, including synthesized audio before local processing, and resume from it after a downstream failure. Make a necessary paid retry visible. The runner already checks completed stage hashes, but an interruption before a synthesized voice is persisted can repeat a paid call. Surface pause-tightening and mastering fallbacks at review. Complete the shared idea according to the selected cuts' dispositions. [Stage runner](../apps/pipeline/src/stages/runner.ts) · [Voice stage](../apps/pipeline/src/stages/voice.ts)

Make the existing schedule control show the intended zone and persist an explicit instant. A successful scheduling request leaves a private, scheduled upload. Reconcile remote status on refresh or a durable follow-up before recording actual publication. Show failures and retry the appropriate operation from the project page. Wider channel scheduling and analytics follow M3.

**Accept when** a reviewer sees the exact private remote ID, both language fields, disclosure, and expected credits for their cut. Replaying the upload reuses the ID. An interrupted local mastering or render resumes from saved audio/assets. A voice-setting change invalidates narration and downstream artifacts for just that cut. A visual edit preserves its approved voice. A stale review cannot publish a different render. A simulated schedule transitions from scheduled to public only after remote confirmation. Record target-channel scheduling behavior separately when an approved release is available.

## Release rehearsal

Run the first two slices in order. Preview and localized publishing can then progress independently. Finish soundtrack audition against the preview, integrate the final render gate, and rehearse the entire flow.

- **Editorial acceptance.** Start with a fresh sourced topic, create both cuts through Ideas/Projects, inspect every claim and agree that the visual shows the mechanism described. Read Russian labels, numbers and phrasing aloud. A reviewer can locate the approved script, visual revisions and publish decision in the dashboard without relying on local helper files.
- **Picture and sound.** Inspect phone-size drafts and extracted frames from both 1080×1920, 30 fps finals. Inspect the full timeline including the hook, scene transitions and outro. Every interval must carry a deliberate visual, including a deliberate hold or continuation. Repair blank frames, plain-background gaps and unsupported diagrams. Fill and center the explanatory animation. Labels name parts, objects or quantities. Begin immediately with the visual. Keep opening titles, source banners and AI banners out of the video. Put sources/credits and accurate synthetic-media metadata in the upload. The reference cuts with native explanatory SVGs used `containsSyntheticMedia=false`.
- **Caption and narration baseline.** Bundle Latin and Cyrillic Inter. Keep captions centered, fixed at 64 px in the final, up to three words per phrase, with a raised bottom placement at 68% or the established top option where the subject needs it. Preserve fixed sizing and whole-phrase display without karaoke highlights. Use ElevenLabs Jade (`g7LVvkPWALzPxOQbF6OE`), `eleven_v3`, natural pace, stability 0.5, character-based alignment and forced-alignment fallback. Preserve the 0.25 s pause cap and the low shelf/compression plus −14 LUFS narration target. Check the mastered audio against caption timing in both languages, then listen to the final mix. [Caption geometry](../apps/renderer/src/props.ts) · [Caption chunks](../apps/renderer/src/captions.ts) · [Mastering](../apps/pipeline/src/audio/mastering.ts)
- **Engineering acceptance.** Add CI for `pnpm typecheck`, `pnpm test` and `pnpm test:e2e` at the start of M3. Run those same checks on the release candidate. Extend the golden path with linked cuts, stale versions and a music/voice-only pair. Exercise the real dashboard, Inngest and Postgres locally with fake paid ports and a real Remotion render. Interrupt one job and retry. Confirm one approved final and upload per cut, intact sibling artifacts, and correct state after a restart.
- **Channel acceptance.** In a controlled live rehearsal using the configured providers, inspect the two private uploads, play them on a phone, and compare stored IDs, titles, language, credits, disclosure and visibility to YouTube. Use the normal publish gate for a cut intended for release. Keep a record of draft/full render times, review corrections, paid calls, remote IDs and any live capability still unverified. For this new topic, use the existing template and shipped components through the editor. A rehearsal that needs topic-specific code, an untracked script, direct DB repair or a post-upload language patch leaves M3 open.

## Input from the channel owner

Start with one channel, English plus an optional linked Russian cut, manual approvals and voice only. A licensed instrumental with its credit terms and an example of the desired mood would allow a real music audition. An example where depth changes the explanation will guide the first 3D trial. A chosen release time and intended timezone will let the team verify a real scheduled release. Hosting, discovery auto-shortlisting and additional provider budgets can wait for their milestones.
