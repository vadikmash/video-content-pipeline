# M2.5 · Continuous, authored animation for Fully animated Shorts

**Outcome.** Claude can art-direct and author a sequence of Remotion TSX that explains a physical change across several narration beats. An editor can create or regenerate a Fully animated Short through the existing dashboard, see the resulting full video at review, and retain the previously reviewed cut if generation fails. Demonstrate the outcome with the saved popcorn narration, first on an 11-second excerpt and then on its complete 39.1-second cut.

**Status.** This is an implementation plan. PR #7 at `3eb0f9e` implements the first Fully animated mode and exercised it with the real Claude Opus 5.5 API. Start from the latest PR head containing this plan or its merged successor. The motion toolkit, generated TSX execution, visual critique and acceptance results below are planned. M2.5 precedes M3. ## Pilot and art direction

Use beats `b3`–`b5`. In the baseline, `b3` starts at 12.804 s, `b4` at 15.916 s, `b5` at 19.137 s and `b6` at 23.866 s. At 30 fps the pilot covers composition frames **384 through 715 inclusive**. Derive these bounds from the loaded revision. The pilot runs with the corresponding narration and captions. Preserve its global word IDs when previewing the excerpt.

| Spoken cue in this revision | Intended picture and movement |
| --- | --- |
| “heats” (word 40), “vapor” (46) | Begin with an asymmetrical cutaway of a single kernel. Show water among the starch inside a continuous hull. Move the camera toward the trapped moisture, with a gradual onset of heat and localized vapor movement. |
| “builds pressure” (51–52) | Hold the silhouette in view while vapor stays confined. Increase pressure cues at the hull, build tension, then briefly hold. The shell remains intact. |
| “ruptures” (59), “expands” (64) | Split the same shell at a visible seam. Reveal the expansion of starch through that opening, with fast initial motion, slower settling and small following fragments. Keep the origin of the burst visible. |

Choose a drawn scientific cutaway with a warm hull, pale textured starch and cool moisture. Establish a recognizable contour, a light direction and three legible depth layers. Reserve space for the actual caption boxes. Let framing, scale and negative space change with the explanation. Capture the accepted palette, geometry, proportions, camera poses and an image of the kernel for reuse. The pilot is a real sequence revision to embed in the final storyboard.

## Sequence contract and motion toolkit

1. Keep `Scene` as the beat-level record for timing, captions and editorial descriptions. Extend persisted `Scene.visual` with a discriminated `animationSequence` variant containing a project-scoped immutable manifest ref, sequence ID and a brief description. Adjacent beats in the same sequence reference the same manifest. This fits the existing `storyboards.scenes` JSONB and preserves review transaction semantics. Keep generated sequence refs outside the model's general mixed-media planner schema. [Schemas](../packages/core/src/schemas.ts) · [DB schema](../packages/db/src/schema.ts)
2. Define a versioned sequence manifest alongside `packages/core/src/animation.ts`. Include ordered beat IDs, narration identity and timing digest, global start/end frames (half-open), FPS, semantic cues, start/end object poses, style reference, source digest, toolkit/compiler versions and seed. Store actual TSX as immutable UTF-8 blobs under `projects/<projectId>/animations/…`. A manifest pins its exact validated source. Model output provides source and cue names. Trusted code assigns keys, hashes and ranges.
3. Derive endpoints using the current `visualTimeline` rounding policy. The first sequence starts at frame zero and the last includes the existing audio-tail hold. Each timed beat belongs to exactly one contiguous sequence. Collapse adjacent sequence references by ID/digest. Reject gaps, overlaps, noncontiguous reuse, duplicate beat membership and mismatched narration. Preserve beat intervals separately for caption placement. Keep all v1 animation, mixed-media and carried-visual playback compatible. [Visual timeline](../apps/renderer/src/visual-timeline.ts) · [FactShort](../apps/renderer/src/FactShort.tsx)
4. The authored module exports a pure React sequence receiving local frame, FPS, size, seed, named cue frames and the style/object reference. Resolve a cue by rounding the global word edge to a composition frame **before** subtracting sequence start. Permit bounded signed frame offsets for anticipation and follow-through. Validate ordered cues where a particular track requires them, including anchors that quantize to the same frame. The scene evaluates directly at any frame. Stable object coordinates and one visual clock carry through each internal beat. At intentional cuts, persist the planned relationship between outgoing and incoming poses, camera and scale.
5. Put trusted, topic-independent motion helpers in the renderer and export a single authored-module import. Provide camera pan/zoom around a specified subject point; explicit hold, linear, ease-in, ease-out, cubic Bézier and damped spring timing; anticipatory and settling keyframes; seeded particle bursts with bounded count, lifetime and per-particle variation; matched-topology path morphs with validated endpoints. Report incompatible paths at validation. Separate path segments can depict a torn shell. Use stable element IDs and a fixed layer order. Test each feature at representative frames. Only use a feature in the pilot when its effect helps explain the mechanism.
6. Keep v1 vector rules and historical template behavior readable. TSX can compose its own SVG silhouettes, groups, clipping, gradients, textures, local components, layout and frame math around the shared toolkit. It owns the visual layer for a whole sequence. The trusted `FactShort` still owns narration, caption layout, music, duration, poster and final assembly. Bump the producing template and toolkit versions when their output changes. Verify APIs against the pinned Remotion `4.0.540` and installed references for timing, sequencing and multi-scene composition. [Renderer guidance](../apps/renderer/AGENTS.md)

## Run authored TSX as project content

Use a disposable local container to compile and render the authored visual layer. Docker already supports the local DB workflow. This adds one explicit runtime dependency for new TSX sequences. An unavailable worker produces an actionable stage error and the current review stays available. No per-sequence manual permission step is needed.

- Build a pinned worker image from trusted Remotion, React, compiler, font and toolkit dependencies. Preinstall Chromium and the encoder at image build time. The trusted wrapper registers the visual composition. It supplies only the current sequence props, reference geometry and bundled assets. Start a fresh job for each source revision/profile or reuse its verified artifact by hash.
- Preflight source size, AST shape, static module imports, export signature and types. Allow local helper components, SVG/React and the documented toolkit. Reject external resource URLs, dynamic loading, raw HTML/script, Node/browser I/O, time-dependent calls and unseeded randomness. Run compiler and all execution inside the isolation boundary. Typechecking and syntax validation provide model repair feedback. They cannot grant host permissions.
- Use an unprivileged job, read-only image, private temp directory with bounded scratch/output, dropped capabilities and resource/time limits. Supply read-only copies of the named inputs, a fresh empty output directory and zero host credentials. Disable external networking; the worker's renderer and Chromium may communicate over its private loopback. Exclude the checkout, `.env`, DB, host blob server, container socket and other projects. Keep trusted container launch and project access checks in the provider. Confirm the chosen Chromium configuration runs under those restrictions on the development machine.
- Return a silent, opaque visual-only video with the manifest's exact frame count and FPS. Use high-quality intraframe intermediate video for the full profile and a small web-playable video for draft. Probe dimensions, stream count, duration/frame count, format and byte limits, accept only expected regular files, then store through `BlobStore`. Discard the temp job. Handle worker cancellation and timeout by killing the full job. Keep diagnostics short and scrubbed.
- `render-remotion` resolves verified sequence refs for the current project, obtains the matching intermediate, then maps it to one trusted `OffthreadVideo` visual spanning the sequence. Continue using the process-wide trusted `getBundle()` for final assembly. The desktop Studio and dashboard receive playable asset URLs and regular props. Keep generated modules out of the trusted bundle and out of the repository. Test seeking, exact last frame and local codec decoding through the real adapter.
